Lords of the Realm II

01

Asset formats

In progress

The gate for everything downstream. Each format is validated across the whole corpus, not one lucky sample — PL8 self-verifies because every frame must end exactly on the next frame's declared offset.

  • ✓PL8 header, frame table, RLE and raw storage — 291/291
  • ✓.256 palettes — 6-bit VGA, scaled to 8-bit
  • ✓PL8 isometric family — all five per-frame shapes — 2502/2502 frames
  • ✓Hit-test region maps recognised structurally, not by filename
  • ✓Every PL8 file decodes — 291/291, 21,344 frames
  • ✓“Raw sub-mode 2” dissolved — the per-frame shape byte decides, not the header
  • ○Which palette pairs with which sprite set
  • ✓L2_maps.dat container — 80 slots of 32,961 bytes, 44 used
  • ●Map tile→lattice mapping — best fit only 72%
  • ✓.eng text — three unrelated formats sharing an extension
  • ✓.skr battle scenarios — arithmetic closes exactly
  • ○CASTLES.DAT and .SAF

04

Battle sandbox

In progress

The first milestone that is genuinely a piece of the finished engine rather than scaffolding — and where the pathing work lives. A battle now runs and draws itself: real .skr terrain, auto-tiled river banks, a bridge, and both liveries of men walking, fighting and falling, stepping the simulation tick by tick.

  • ✓Unit and figure data structures — 80-figure ceiling, stable indices
  • ✓Movement, elevation rules, cell swapping
  • ✓Pathfinding — weighted and deferred, deliberately not Dijkstra
  • ✓Melee and missile resolution — every ranking the manual states, asserted
  • ✓Melee table checked against the binary — 11/11 rows exact
  • ✓Battlefield terrain, auto-tiling, sprites, facings, animation
  • ✓All 20 shipped battlefields build — 128,000 cells, every index valid
  • ✓Units, formations, and the AI driving them — all 17 handlers reachable
  • ✓Sieges — the wall, the gate, the way in, and the 14 siege orders — the castle’s layout is ours and says so
  • ✓Missiles fly — a shot traverses, and hits whoever is in the cell it enters
  • ✓“Will you take the field?” — screens 0x12 and 0x13; the turn suspends until the player answers
05

Oracle and differential testing

Started early

Turns the original binary into a test fixture — and the big lesson of this phase is that the binary is the fixture, not the running game. Reading the executable answers nearly everything, instantly and with no window to steal focus. Launching the original turned out to be the last resort, not the second.

  • ✓Ghidra 12.1.3 + headless analysis pipeline
  • ✓Whole binary decompiled and greppable — 2,452 functions in 22 seconds
  • ✓Symbol database shared between Ghidra and the docs — 1,290 functions, 572 globals
  • ✓Battle tables read from the executable — disk and live memory identical
  • ✓Runtime constants recovered from the MOV immediates that write them
  • ✓Kingdom economy tables checked — every value right, two layouts wrong
  • ✓ddraw.dll proxy and hard-link sandbox — install untouched
  • ○Pixel diff against the original's framebuffer — never yet attempted
06

Kingdom layer

In progress

The turn-based half: the larger and less charted body of rules, and the one place the printed manual has been caught wrong twice. Every economic constant lives in the executable rather than a data file, which is much of the reason to build an open engine at all.

  • ✓Counties, population, happiness, taxation
  • ✓Seasons, weather, crops, livestock, food stores
  • ✓Weapons manufacture, wages, industry
  • ✓The seven-phase turn machine — a 23-entry pipeline the driver walks
  • ✓Shipped save reproduced end to end — five stages, nothing adjusted
  • ○Stubs left honest: AI handlers, bankruptcy stages, the event table
  • ✓Sieges on the campaign map — engines, seasons, the assault gate; five real snapshots reproduced
  • ○The castle designer — which is not in this executable
07

Netcode

In progress

The original's networking is abandoned rather than studied — it is replaced outright, not reimplemented. What matters is determinism, which is a property of the simulation and was designed in from its first line.

  • ✓Deterministic primitives — frozen PRNG, Q16.16 fixed point, one canonical encoding
  • ✓Lockstep session — command ordering, checksums, desync dumps, replay
  • ✓TCP transport, non-blocking, no threads and no clock
  • ✓The battle simulation run over a real socket — two peers, identical every tick
  • ○Lobby, host and join
  • ○Beyond loopback — real loss, NAT, MTU, head-of-line blocking
08

Modding platform

Started

The actual destination. Designed in from the first crate rather than retrofitted: rules live in data files, and assets load through an overlay filesystem. Assets shadow; rules accumulate — the asymmetry is deliberate.

  • ✓Virtual filesystem with mod-directory overlay — proven with synthetic art
  • ●Data-driven rulesets replacing hardcoded constants
  • ○Mod packaging, load order, conflict reporting
  • ○Format and ruleset documentation for mod authors
